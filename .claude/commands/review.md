변경된 코드에 대해 플로우 기반 QA 리뷰를 수행합니다.
모든 판단은 **코드를 직접 확인한 근거**로만 합니다. 추측·추론으로 결론 내리지 않습니다.

## 1단계 — 변경 파일 파악

`git diff --name-only` 로 변경 파일을 확인합니다.

⚠️ pathspec 에 `**` 를 쓰지 않습니다. 기본 pathspec 은 `**` 를 glob 으로 해석하지 않아
`'src/**/*.ts'` 가 **`src/` 직속 파일(`app.module.ts`·`main.ts`)을 건너뜁니다.**
`-- src/`(디렉터리) 또는 `-- ':(glob)src/**/*.ts'` 를 씁니다.
"프로덕션 변경 0건" 같은 판정을 이 명령에 근거해 내리므로 누락이 곧 오판입니다.

## 2단계 — grep 전수 확인

변경된 함수·API·타입 이름으로 **프로젝트 전체** grep 을 실행합니다.

- 부분일치가 가능한 심볼은 경계를 포함한 정확 패턴으로 셉니다
  (`JwtAuthGuard` 는 `OptionalJwtAuthGuard` 까지 셉니다)
- 파일 부분 읽기(offset/limit)만으로 "전체 정상" 판단 금지
- 카운트가 기대와 다르면 **결론을 바꾸기 전에 측정 명령부터 검산**합니다
- **0건은 대조군 없이는 근거가 아닙니다** — 전수검색이 0건이면 그 패턴이 매치될 수 있음을
  **먼저 증명**합니다(반드시 잡히는 문자열로 양성 대조). 검산 없는 0건을 "없음"의 근거로 쓰면
  그 판정이 곧 오진입니다
- **리터럴 검색은 `grep -F` 또는 홑따옴표** — 이중따옴표 안의 `$` 는 셸이 먹어
  정규식 앵커(줄 끝)가 됩니다. `"...\$foo"` 로 센 결과는 0건이 나와도 실재할 수 있습니다
- **재현은 대용 명령이 아니라 실제 명령으로** 합니다 — `seq 1 38 | head -30` 은 SIGPIPE 가 안 나지만
  `git log | head -30` 은 **exit 141** 이 납니다(출력 크기·타이밍 차이). 파이프를 없애려면 `-n 30` 을 씁니다

## 3단계 — 플로우 리스트업

변경 내용을 요청 단위 플로우로 분류합니다.

`요청 → Controller → Service → Port/Repository → 외부 시스템 → 응답`

## 4단계 — 플로우별 추적 검증

각 플로우마다 확인합니다.

1. **타입 체인 1:1 대조** — DTO → 서비스 반환 → 응답 스키마가 필드 단위로 일치하는지
2. **필드 누락** — 새로 추가한 필드가 체인 전체에 포함되는지
3. **중복 호출** — 동일 함수·API 가 불필요하게 여러 번 호출되지 않는지
4. **에러 경로** — `defineDomainError` 로 정의했는지, status·code 가 테스트에 정확히 고정됐는지
5. **부수효과** — 의도한 데이터만 바뀌는지

## 5단계 — 규약 위반 검사

[`.claude/rules/code-patterns.md`](../rules/code-patterns.md) 의 신규 기능 체크리스트를 그대로 적용합니다. 특히:

- 외부 시스템을 Port 없이 직접 호출하지 않았는지
- 외부 API 요청·응답 **본문을 로그에 남기지 않았는지**
- 인메모리 상태·타이머를 쓰지 않았는지 (레플리카 3개)
- liveness 헬스체크에 외부 의존을 추가하지 않았는지
- 전역 필터·인터셉터를 건드렸다면 **적용되면 안 되는 응답**을 확인했는지
- 빌드 진입 설정을 바꿨다면 `Dockerfile` COPY 목록을 확인했는지

발견 사항을 **심각도 순**으로 보고합니다. 각 항목에 파일:줄과 근거를 답니다.
문제가 없으면 "확인한 범위"와 "확인하지 못한 범위"를 명시합니다.
