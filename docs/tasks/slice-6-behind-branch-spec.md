## 1. 목표와 범위

본편의 결말 뒤 사용자가 A/B 중 하나를 골라 **서로 다른 비하인드 결과**를 읽게 한다. 선택은 서사적으로 의미 있는 첫 선택으로 보존하되, 재독 때는 두 결과를 모두 탐색할 수 있게 한다.

이 Slice는 체험 모드의 개인화 리더에만 적용한다. 시연 모드는 기존 선형 콘텐츠 흐름을 유지한다.

### 확정된 원칙

- 본편은 공통 **1~5쪽**이다.
- 본편 뒤에는 삽화 없는 **A/B 분기 UI**를 표시한다. 이 화면은 책 페이지가 아니며 페이지 번호를 갖지 않는다.
- 선택 결과는 **6쪽**이며 A와 B가 서로 다른 원고·템플릿 삽화·개인화 결과를 가진다.
- 개인화 시작 시 공통 본편 5장과 A/B 결과 2장을 모두 생성한다. 따라서 템플릿/개인화 이미지 자산은 세션당 **7장**이다.
- 한 번의 독서 경로에는 공통 5쪽과 선택한 결과 6쪽만 보여 총 **6쪽**이 표시된다.
- 첫 A/B 선택만 영구 보존한다. 재독 중 다른 결과를 열람하는 행동은 첫 선택을 바꾸지 않는다.

## 2. 사용자 플로우

```mermaid
flowchart TD
  start[개인화 생성 시작] --> generate[공통 5장 + 결과 A/B 2장 선생성]
  generate --> main[본편 1~5쪽 읽기]
  main --> choice[A/B 분기 UI]
  choice -->|건너뛰기| end[완독 화면]
  choice -->|첫 A/B 선택| confirm[선택 확인 모달]
  confirm -->|확정| persist[첫 선택 영구 보존]
  persist --> outcome[선택 결과 6쪽]
  choice -->|재독 중 A/B 열람| outcome
  outcome --> end
  end --> reopen[재독]
  reopen --> main
```

### 분기 UI

- 5쪽의 다음 동작은 분기 UI를 연다.
- UI는 제목, 안내 문구, A/B 버튼과 각 선택지의 짧은 설명만 가진다. 별도 삽화나 개인화 이미지를 생성하지 않는다.
- `건너뛰기`는 선택을 저장하지 않고 완독 화면으로 이동한다. 다음 재독에서는 다시 분기 UI를 연다.
- 첫 선택은 확인 모달에서 확정한다. 오조작 방지를 위한 장치다.
- 이미 첫 선택이 저장된 세션의 재독에서는 확인 모달 없이 A/B 결과를 모두 열람할 수 있다. 이는 탐색 상태일 뿐 영구 선택을 갱신하지 않는다.

### 페이지별 실패

- 공통 본편 1~5쪽이 모두 준비되면 읽기를 시작할 수 있다.
- A/B 결과는 서로 독립된 상태로 생성·재시도한다.
- 아직 선택하지 않은 분기의 실패는 본편 읽기나 반대 분기 선택을 막지 않는다.
- 사용자가 고르려는 분기가 실패 상태이면 해당 버튼을 비활성화하고 그 자리에서 재시도 동작을 제공한다.

## 3. 콘텐츠 및 이미지 모델

현재의 선형 `story_pages` 모델은 동일한 6쪽의 A/B 결과를 표현할 수 없다. 공통 콘텐츠와 분기 콘텐츠를 같은 테이블에서 관리하되 `branch_key`로 구분한다.

| 종류 | `page_no` | `branch_key` | 자산 수 |
|---|---:|---|---:|
| 본편 | 1~5 | `common` | 5 |
| 비하인드 결과 A | 6 | `a` | 1 |
| 비하인드 결과 B | 6 | `b` | 1 |

`branch_key`는 nullable 값으로 두지 않는다. MySQL의 복합 UNIQUE에서 `NULL` 행이 중복될 수 있으므로 `common | a | b` 열거형으로 저장한다.

### 콘텐츠 메타데이터

분기 UI는 콘텐츠가 소유한다. A/B마다 최소 다음 데이터를 둔다.

- `title`: 선택지 제목
- `description`: 선택지의 짧은 설명
- `branch_key`: `a` 또는 `b`
- 결과 6쪽의 `body_text`, `illustration_prompt`, `base_image_key`, 등장인물 정보

선택 UI에 이미지가 없으므로 기존에 제안됐던 분기 카드 `thumbnail_key`와 `subtitle`은 이번 범위의 필수 컬럼이 아니다. 필요해질 때 콘텐츠 요구에 맞춰 추가한다.

## 4. 세션 데이터와 불변 규칙

### 4.1 개인화 이미지

`session_page_images`에 `branch_key`를 추가하고 식별 제약을 다음처럼 바꾼다.

```text
UNIQUE(session_id, page_no, branch_key)
```

이로써 같은 세션의 `page_no = 6`에 A와 B 이미지를 각각 한 개씩 저장한다. 스토리지 키도 충돌하지 않게 분기 값을 포함한다.

```text
pages/{sessionId}/common/page-5.png
pages/{sessionId}/a/page-6.png
pages/{sessionId}/b/page-6.png
```

### 4.2 첫 선택 기록

첫 선택은 별도 `session_branch_choices` 테이블에 기록한다.

| 열 | 제약 | 의미 |
|---|---|---|
| `session_id` | UNIQUE, FK | 세션당 최초 선택은 하나 |
| `branch_key` | `a` 또는 `b` | 최초로 확정한 분기 |
| `selected_at` | NOT NULL | 확정 시각 |

재독의 A/B 열람은 이 테이블을 수정하지 않는다. `건너뛰기`도 행을 만들지 않는다.

첫 선택 저장은 트랜잭션과 `UNIQUE(session_id)` 제약으로 보호한다. 동시 요청으로 서로 다른 값이 들어오더라도 먼저 확정된 선택만 보존한다.

## 5. 생성 파이프라인

`POST /sessions/:id/personalize`는 공통 5개와 분기 2개, 총 7개의 개인화 이미지 작업을 초기화하고 비동기로 실행한다.

```text
(1, common) ... (5, common), (6, a), (6, b)
```

- 동일 세션의 재호출은 기존 7개 작업을 재사용하는 멱등 동작이다.
- 기존 실패 페이지 재시도 API는 `branchKey`까지 대상으로 식별할 수 있어야 한다. 공통 6쪽과 분기 6쪽이 혼동되어서는 안 된다.
- 응답은 전체 7장의 상태와 함께 `isMainStoryReady`(공통 1~5쪽 모두 성공)를 제공한다. 전체 생성 상태가 아직 끝나지 않았어도 `isMainStoryReady`이면 리더 진입을 허용한다.
- 모든 작업 성공만 세션의 최종 완료로 간주한다. 분기 하나가 실패해도 독서를 막지는 않으며 해당 분기만 재시도 가능하다.

## 6. API 계약 초안

모든 경로는 `/api/v2` 하위이고 세션 소유자 인증이 필요하다.

### `GET /sessions/:id/after-story`

분기 UI와 결과 열람에 필요한 상태를 반환한다.

```json
{
  "sessionId": "session-uuid",
  "firstBranchChoice": "a",
  "choices": [
    {
      "branchKey": "a",
      "title": "...",
      "description": "...",
      "pageNo": 6,
      "status": "succeeded",
      "imageUrl": "https://..."
    },
    {
      "branchKey": "b",
      "title": "...",
      "description": "...",
      "pageNo": 6,
      "status": "failed",
      "imageUrl": null
    }
  ]
}
```

`firstBranchChoice`는 선택 전 또는 건너뛴 세션에서 `null`이다. 결과의 본문은 일반 페이지 조회 응답에 포함시키거나 이 응답에 포함시키되, 구현 때 계약 하나로 고정한다.

### `POST /sessions/:id/after-story/choice`

최초 선택만 저장한다.

```json
{ "branchKey": "a" }
```

- 선택 기록이 없으면 `201 Created`로 생성한다.
- 같은 값의 반복 요청은 현재 기록을 반환하는 멱등 성공으로 처리한다.
- 다른 값의 재요청은 `409 FIRST_BRANCH_ALREADY_CHOSEN`을 반환한다.
- 재독 중 다른 결과를 보는 경우 이 API를 호출하지 않는다.

## 7. 수용 기준과 검증

- 공통 본편 5쪽과 A/B 결과 6쪽이 각각 다른 템플릿 원고·삽화 프롬프트로 존재한다.
- 개인화 시작 시 7개 작업이 초기화되고 A/B 결과가 모두 생성 대상에 포함된다.
- 본편 5쪽 완료 시, 분기 결과의 성공 여부와 무관하게 리더에 진입할 수 있다.
- 5쪽 다음에서 이미지 없는 A/B 선택 UI와 `건너뛰기`를 볼 수 있다.
- 최초 선택은 확인 뒤 한 번만 저장되며 다른 값으로 덮어쓸 수 없다.
- 건너뛰기는 선택 기록을 만들지 않고, 재독 시 분기 UI를 다시 표시한다.
- 재독에서는 저장된 최초 선택을 유지하면서 A/B 결과를 모두 열람할 수 있다.
- A/B 결과 중 하나만 실패했을 때 반대 결과와 본편은 정상 열람되고, 실패한 결과만 재시도할 수 있다.
- 세션·페이지·분기 소유권 검증을 포함한 API 단위/E2E 테스트를 추가한다.

## 8. 비용과 트레이드오프

선택 전 A/B 결과를 모두 생성하므로 기존 선형 6장 생성에 비해 세션당 생성량은 7장으로 약 16.7% 증가한다. 저장량도 선택하지 않은 결과 1장만큼 증가한다.

이 비용을 감수하는 이유는 선택 직후의 생성 대기 없이 결과를 즉시 보여 주고, 재독 시 두 결과를 모두 열람하게 하기 위해서다. 비용 예산은 Slice 4의 이미지 생성 단가와 함께 7장 기준으로 다시 산정한다.
