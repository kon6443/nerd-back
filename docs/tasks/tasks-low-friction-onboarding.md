## 1. 대회 요구사항 — 무엇을 충족해야 하는가

공지가 제시한 선택지는 셋이고, 뒤로 갈수록 불이익이 커진다.

| 방법 | 내용 | 평가 영향 |
|---|---|---|
| **1-A 한시적 개방** | 심사 기간 동안 로그인 없이 핵심 기능 이용 | 권장 — 불이익 없음 |
| **1-B 데모 버전 분리** | 별도 URL 로 로그인 없는 데모 제공 | 권장 — 불이익 없음 |

**핵심 문장**: *"로그인 절차가 그대로 남아 있는 경우 심사위원과 일반 투표자가 서비스를 직접 체험하지 못한 상태에서 평가·투표하게 될 수 있다."*

| 현재 카피 | 「10초면 가입 끝!」 「이름·이메일은 받지 않아요」 | `login/page.tsx:19-51` |
| 비로그인 체험 경로 | `(demo)` 라우트 그룹 `/library/*` 존재 | `docs/tasks/demo-interactive-flow-spec.md` |

> 즉 **「개인정보를 수집하지 않는다」는 이미 사실**이다. 공지의 방법 3 리스크(수집·파기 책임)는 애초에 거의 발생하지 않는다.

### 2.2 갭 — 그럼에도 남는 두 가지

**갭 A. 핵심 기능이 여전히 로그인 뒤에 있다.**

서비스의 핵심 가치는 「**내 얼굴**이 동화 주인공으로 합성되는 경험」이다. 그런데:

- `(demo)` 경로(`/library/*`)는 **프리셋 얼굴(남/녀 2종)** 체험이라 「내 얼굴」이 빠진다 — `demo-interactive-flow-spec.md` §2 Step 2
- 「내 얼굴」 경로(`(trial)/stories/[slug]/capture`)는 `AuthGuard` 뒤에 있다 — `apps/back/src/modules/story-session/story-session.controller.ts` 9개 라우트 전부

→ 심사위원은 **아이디·비밀번호를 만들지 않으면 핵심 가치를 볼 수 없다.** 사용자 제안(카피 순화)만으로는 이 갭이 남는다.

**갭 B. 🚨 운영 환경에서 회원가입이 차단되어 있을 수 있다.**

```
SIGNUP_ENABLED_BY_ENV = { LOCAL: true, PROD: false }   // auth.constants.ts:12-15
```

PROD 기본값이 **가입 차단(403 `SIGNUP_DISABLED`)** 이다. `SIGNUP_ENABLED=true` 환경변수로만 열린다.
그런데 이 변수는 `infra/prod_nerd_back.yml` 에 없고 **서버상의 `${ENV_FILE_PATH}`(저장소 밖)** 에서만 주입된다.

→ **2026-09-20 해소.** 사용자 확인 결과 운영 env 에는 `SIGNUP_ENABLED=true` 가 이미 주입되어 있었다.
다만 **환경변수 하나가 빠지면 즉시 가입이 막히는 구조**가 심사 기간에 너무 위험하므로,
사용자 지시로 **`SIGNUP_ENABLED_BY_ENV` 의 PROD 기본값을 `true` 로 전환**했다. 킬 스위치(`SIGNUP_ENABLED=false`)는 그대로 살아 있다.

## 3. 방향 선택 — **옵션 B 채택** (2026-09-20 확정)

사용자 결정: **옵션 B**, 단 **플래그 한 줄로 A 로 되돌릴 수 있게** 미리 만들어 둔다.
추가 결정: 닉네임에 **한글 허용**하고 화면 표기를 「닉네임」 으로 바꾼다.

### 플래그 구조 — 「딸깍」 이 성립하는 지점

`packages/contracts/src/feature-flags.ts` 에 **두 개**가 있고, 위가 상위 스위치다.

| 플래그 | 켜면 | 끄면 |
|---|---|---|
| `GUEST_ACCESS_ENABLED` | 「닉네임 없이 바로 체험하기」 버튼 + `POST /auth/guest` 개방 | 버튼이 사라지고 엔드포인트는 403. **아래 값과 무관하게 자동 입장도 멈춘다** |
| `GUEST_AUTO_ENTER` | **사이트에 들어오면 아무것도 누르지 않아도** 임시 계정이 생기고 로그인 상태가 된다 | 자동 입장 없음. 버튼으로만 들어간다 (= 옵션 B 의 원래 모습) |

```
① 백엔드 환경변수 GUEST_ACCESS_ENABLED ('true'|'false')   ← 있으면 이김. 백엔드만 잠근다(비상용)
        ↓ 없으면
② packages/contracts/src/feature-flags.ts                 ← 프론트와 백엔드가 같이 보는 값
   export const GUEST_ACCESS_ENABLED = true;   // 버튼·엔드포인트
   export const GUEST_AUTO_ENTER      = true;  // 무입력 자동 입장
```

⚠️ **`GUEST_AUTO_ENTER` 를 켜면 방문자 수만큼 계정 행이 쌓인다.** 대회가 끝나면 끄는 것을 전제로 한 값이다.

- **B → A 전환 = ② 를 `false` 로 고치고 두 앱 배포.** 버튼이 사라지고 엔드포인트도 403 이 된다.
- 🚫 ① 만으로 끄면 **프론트 버튼은 남는다**(빌드 타임 상수라 런타임 env 가 닿지 않는다) — 「눌렀더니 403」 이 된다. 비상 잠금 전용이다.
- 회원가입 플래그(`SIGNUP_ENABLED`)와 **구조가 다르다.** 그쪽은 백엔드 전용이라 contracts 에 없다.

## 3-1. 검토했던 선택지 (기록)

### 옵션 A — 카피·UX 순화만 (사용자 원안)

`/login` 의 「회원가입」 프레이밍을 「이용자 식별자 만들기」로 바꾼다. 백엔드 무변경.

- 변경 범위: `login/page.tsx` 의 `MODE_COPY` 및 진입 버튼 문구
- 대회 기준 충족도: **방법 3에 해당** — 로그인 절차가 남아 있다
- 장점: 위험 0, 30분이면 끝남
- 한계: 갭 A 미해소. 심사위원이 여전히 입력해야 한다

### 옵션 B — 옵션 A + 게스트 원클릭 입장 ⭐ 권장

버튼 하나로 서버가 임의 `loginId`/`password` 를 생성해 세션 쿠키를 발급한다.
**기존 인증 플로우(쿠키·가드·세션·스토리 세션)를 한 줄도 바꾸지 않는다** — 자격증명을 사용자 대신 서버가 만들 뿐이다.

- 백엔드: `POST /api/v2/auth/guest` 1개 추가 (내부적으로 기존 `signup` 재사용)
- 프론트: 「로그인 없이 바로 체험하기」 버튼 + 홈/서재 CTA 연결
- 대회 기준 충족도: **방법 1-A 충족** — 로그인 없이 핵심 기능 이용
- 추가 고려: 게스트 계정 레이트리밋, 데이터 보존 정책(기존 임시사진 삭제 정책과 정합 — `data-deletion-temporary-photo-spec.md`)

### 옵션 C — 옵션 B + 약관·개인정보처리방침 페이지

- 현재 두 페이지 **모두 없음** (`app/` 스캔 결과 0건)
- 수집 항목이 사실상 없으므로 짧게 쓸 수 있다
- 방법 3을 택하지 않더라도 **있으면 심사 신뢰도에 유리**

    세션 쿠키가 교체된다. 완전히 비우려면 시크릿 창이나 브라우저 쿠키 삭제를 쓴다.

| `GUEST_ACCESS_ENABLED` | `GUEST_AUTO_ENTER` | 로그아웃 버튼 | 게스트 버튼 | 「닉네임 만들기」 | 뜻 |
|---|---|---|---|---|---|
| `true` | `true` | **0** | 1 | **3** | 지금 — 들어오면 자동 로그인 |
| `true` | `false` | **1** | 1 | **3** | 버튼으로만 입장. 로그아웃 복귀 |
| `false` | (무시) | **1** | 0 | **3** | 게스트 기능 전체 off. 수동 가입·로그인만 |

⭐ **어느 조합에서도 「닉네임 만들기」 화면은 그대로 살아 있다**(3건 유지). 자동 입장을 끄면
사용자가 직접 닉네임을 만드는 원래 흐름으로 **상수 한 줄만으로** 돌아온다.

### 레이트리밋 상향 — 분당 10 → 120 (2026-09-20, 실측 근거)

자동 입장이 켜지면 **버튼을 누른 사람이 아니라 방문자 전원**이 `POST /auth/guest` 를 부른다.
버튼 시절의 값(분당 10)으로는 정상 트래픽이 막힌다.

| 근거 | 값 |
|---|---|
| 1회 비용 **실측** (로컬, 터널 DB) | **약 190ms** (scrypt + INSERT). 비교: `GET /health` **1.6ms** |
| 분당 120 = 초당 2회 | 코어 하나의 약 40%. **레플리카 3개**라 실제로는 더 낮다 |
| 순간 폭주 | 이 값이 막지 않는다 — **전역 `short`(1초 20회)** 가 그대로 적용된다(`@Throttle({ long })` 은 `long` 만 덮어쓴다) |

⚠️ 한도가 **IP 기준**인 것이 상향의 핵심 이유다. 모바일은 통신사 CGNAT 뒤에서 **수백~수천 명이
공인 IP 하나를 공유**하고 행사장·회사 망도 같다. 분당 10 이면 같은 망의 11번째 방문자부터 조용히 실패한다.

### 2차 리뷰에서 잡아 고친 것 (2026-09-20)

**플래그 조합 불일치** — 마이페이지가 `GUEST_AUTO_ENTER` 만 보고 로그아웃 버튼을 숨겼는데,
자동 입장의 실제 판정은 두 플래그를 **모두** 본다. 그래서 `GUEST_ACCESS_ENABLED=false` 로 게스트
기능을 통째로 끄면서 `GUEST_AUTO_ENTER` 를 안 끄면, **자동 입장은 멈추는데 로그아웃 버튼만
사라져 아무도 로그아웃할 수 없는** 상태가 됐다.
→ `GUEST_AUTO_ENTER_ACTIVE`(두 플래그의 AND) 하나를 `guestAutoEnter.ts` 가 소유하고
**화면과 판정이 같은 값을 본다.** 🚫 화면에서 `GUEST_AUTO_ENTER` 를 직접 보지 않는다.
반증: 조합 ③ 으로 실제 빌드 → `/me` 에 「로그아웃」 **1건 복귀** 확인(수정 전이면 0건).
