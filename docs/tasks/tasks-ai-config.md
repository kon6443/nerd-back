## 이식 중 발견한 함정 → 우리 규칙

1. **훅은 "작성"이 아니라 "등록 확인"까지가 완료다.** 참고 B 는 잘 만든 가드 훅을 갖고 있으나 `settings.json`에 `hooks` 키가 없고 `settings.local.json`의 `hooks`가 `null`이라 **한 번도 실행되지 않는 죽은 훅**이었다. 훅을 추가하면 등록 여부를 반드시 확인한다.
2. **하위 디렉터리 개인 설정 잔재.** 참고 B 는 `docs/` 안에 `.claude/settings.local.json`(절대경로 포함)이 방치돼 있었다. 저장소 루트 밖·하위에 생긴 설정 사본은 즉시 정리한다.
3. **설정 자기보호 deny 는 순서가 있다.** `Edit·Write(.claude/settings.json)` deny 가 걸린 상태에서는 AI 가 훅을 등록할 수 없다. 설정 작업은 **deny 를 마지막에** 넣는다 (참고 B 가 같은 순서 제약을 명시).

## 훅 등록 — 완료 (2026-08-27)

`.claude/settings.json` 은 AI 쓰기 deny 대상이라 **사용자가 직접 등록했다.** 등록된 블록은 아래와 같다 (`permissions` 와 같은 레벨).

```json
"hooks": {
  "UserPromptSubmit": [
    { "hooks": [ { "type": "command", "command": "sh \"$CLAUDE_PROJECT_DIR/.claude/hooks/check-secrets.sh\"", "timeout": 3 } ] }
  ],
  "PreCompact": [
    { "matcher": "*", "hooks": [ { "type": "command", "command": "sh \"$CLAUDE_PROJECT_DIR/.claude/hooks/precompact.sh\"", "timeout": 20 } ] }
  ]
}
```

등록 직후 실측: 유효 JSON · `permissions` 40/51/11 무손실 · `hooks` 외 변경 0건(`diff` 대조) · 두 스크립트 경로 실존. **훅의 실제 발동은 미검증** — 다음 `/compact` 때 `docs/handoff/` 에 스냅샷이 생기는지 확인한다.

## Lessons

- **문서 4곳을 비교할 때 "가장 긴 것"이 정답이 아니다.** 참고 C 는 834줄 중 700줄이 코드 스타일이고 아키텍처 트리·명령어가 `CLAUDE.md` 안에 있었다 — 앞 100줄의 Always/Ask/Never 표가 그 뒤 700줄에 묻히는 구조로, 우리 서두 규칙("이걸 모르면 틀리게 행동하는가?")의 반례로 쓰인다.
- **"글로벌에 있으니 중복"은 팀 관점에서 틀린 판단이었다.** 처음엔 계획서·버그리포트 템플릿을 "개인 글로벌에 이미 있으니 중복"으로 미도입 처리했다. 그런데 개인 글로벌(`~/.claude/`)은 **그 머신에만** 있어 저장소를 클론한 다른 개발자에게 전파되지 않는다. 팀이 쓸 규약·양식은 **저장소 안에 있어야 공유된다**. → 판단 정정 후 2종을 이관했다. 반대로 `work-history` 골격처럼 **이미 저장소 안의 다른 산출물이 갖고 있는 것**은 진짜 중복이라 넣지 않았다. **"중복"을 따질 때 기준은 파일 개수가 아니라 "팀이 접근할 수 있는 사본이 1개 있는가"다.**
- **스케일은 문서 수가 아니라 라우팅 표 길이가 결정한다.** 참고 B 는 docs 129개를 라우팅 8행으로 운영했다. 완료분을 `archive/`로 빼 라우팅 후보에서 제외한 것이 비결이다.
